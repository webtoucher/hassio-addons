# Mercury Proxy

Аддон для Home Assistant, который запускает сервис
[mercury-proxy](https://github.com/webtoucher/mercury-proxy) — TCP/IP-прокси и REST API
для счётчиков Инкотекс «Меркурий» (200/201/203/206 и другие модели протокола V1),
подключённых по RS485/CAN-шине.

Код прокси в аддоне не живёт: при сборке ставится пакет из его репозитория,
при запуске аддон лишь превращает опции в конфигурационный файл сервиса
и запускает его штатную команду `mercury-proxy`.

## Что делает сервис

- держит последовательный порт (USB-RS485-адаптер) и отвечает счётчикам по протоколу V1;
- поднимает **прокси-порт** — к нему подключается «Конфигуратор» Инкотекс или любая
  программа, умеющая работать с Меркурием по TCP;
- поднимает **REST API** — к нему обращаются интеграции, в том числе Home Assistant;
- повторяет попытку подключить счётчик, которого не было при старте
  (интервал задаётся опцией `reconnect_interval`).

## Сеть и порты

| Порт контейнера | Назначение | Как менять |
| --- | --- | --- |
| `5053/tcp` | Прокси-порт для «Конфигуратора» | Панель **Сеть** аддона |
| `5054/tcp` | REST API | Панель **Сеть** аддона |

Внутри контейнера порты всегда 5053 и 5054 (это стандартные порты сервиса),
наружу выставляются через панель «Сеть» на странице аддона: слева — внешний порт
хоста, справа — неизменяемый порт контейнера.

## Опции

| Опция | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `meters` | список | `37793503` на `/dev/ttyACM0` | Счётчики: `address` (сетевой адрес, обычно серийный номер) и `port` (последовательное устройство или `host:port` другого прокси) |
| `baudrate` | число | `9600` | Скорость последовательного порта; применяется ко всем счётчикам на последовательных портах |
| `timeout` | число, необязательно | по умолчанию сервиса | Сколько секунд ждать ответ счётчика |
| `connect_timeout` | число, необязательно | по умолчанию сервиса | Сколько ждать установки TCP-соединения (только для счётчиков вида `host:port`) |
| `api` | bool | `true` | Включать REST API |
| `api_token` | строка, необязательно | пусто | Ключ доступа к API: не короче 8 символов. Пустое значение — API открыт всем в сети (в логе будет предупреждение) |
| `log_level` | список | `info` | Подробность лога: `debug`, `info`, `warning` |
| `log_console` | bool | `true` | Дублировать лог в консоль, то есть в лог аддона на странице «Лог» |
| `reconnect_interval` | число | `30` | Как часто, в секундах, повторять попытку подключить отсутствующий счётчик; `0` выключает повтор |

После сохранения опций аддон нужно перезапустить: конфигурация сервиса
генерируется только на старте.

## Примеры

### Один счётчик по USB-RS485

```yaml
meters:
  - address: 37793503
    port: /dev/ttyACM0
baudrate: 9600
```

### Несколько счётчиков на одной шине

У каждого счётчика свой адрес, порт — общий; отвечает тот, чей адрес в запросе.

```yaml
meters:
  - address: 37793503
    port: /dev/ttyACM0
  - address: 37793504
    port: /dev/ttyACM0
```

### Счётчик за другим прокси (TCP)

```yaml
meters:
  - address: 37793503
    port: 192.168.1.10:5053
timeout: 5
```

### Стабильный путь к USB-адаптеру

Имена вида `/dev/ttyACM0` и `/dev/ttyUSB0` могут поменяться после переподключения
адаптера. Надёжнее указать путь из `/dev/serial/by-id/`, например:

```yaml
meters:
  - address: 37793503
    port: /dev/serial/by-id/usb-1a86_USB_Single_Serial_54D2073260-if00
```

## REST API

Все маршруты живут под `/v1.0` на порту 5054 (или на внешнем порту из панели «Сеть»).

| Метод | Путь | Что делает |
| --- | --- | --- |
| `GET` | `/v1.0` | Имя и версия API |
| `GET` | `/v1.0/health` | Состояние сервиса и число подключённых счётчиков |
| `GET` | `/v1.0/meters` | Список подключённых счётчиков |
| `GET` | `/v1.0/meters/{serial}` | Один счётчик по серийному номеру |
| `GET` | `/v1.0/meters/{serial}/{command}` | Команда `mercury-base`, параметры в строке запроса |
| `POST` | `/v1.0/meters/{serial}/{command}` | Команда `mercury-base`, параметры в теле JSON |

```bash
curl http://homeassistant.local:5054/v1.0/health
curl http://homeassistant.local:5054/v1.0/meters
curl http://homeassistant.local:5054/v1.0/meters/37793503/get_load_power
```

Если задан `api_token`, каждый запрос несёт заголовок:

```bash
curl -H "Authorization: Bearer <токен>" http://homeassistant.local:5054/v1.0/health
```

## Подключение «Конфигуратора»

1. Поставьте на компьютер «Конфигуратор Универсальный» с сайта Инкотекс
   (раздел «Сервис» → «Программное обеспечение»).
2. Создайте виртуальный COM-порт в режиме **TCP Client** (например, HW VSP3),
   адрес — IP Home Assistant, порт — внешний порт прокси из панели «Сеть» (по умолчанию 5053).
3. В конфигураторе выбирайте созданный COM-порт, скорость 9600, 8 бит, без чётности,
   1 стоп-бит, адрес счётчика — его серийный номер.

Прокси работает с протоколом V1 на скорости 9600 8N1: параметры порта
в самом аддоне не настраиваются, `baudrate` меняет только скорость линии.

## Логи

- Страница аддона → «Лог»: то, что сервис пишет в консоль (`log_console: true`).
- Файл `/data/log/mercury-proxy.log` (ротация: 1 МБ, 5 файлов) — в контейнере,
  доступен через терминал или SSH-аддон.
- На уровне `debug` в лог попадают все пакеты шины в hex.

## Версия прокси

Аддон ставит пакет из репозитория `webtoucher/mercury-proxy` по ссылке из
`build.yaml` (по умолчанию — тег `v2.0.0`). Чтобы попробовать невыпущенный код,
поменяйте `MERCURY_PROXY_REF` на `master` или на хэш коммита и пересоберите аддон.

## Обновление с 0.3.x

Опции `meter_address` и `meter_port` заменены списком `meters`. После обновления
перенесите адрес и порт в первую запись списка; старые ключи Supervisor
покажет в предупреждении, их можно удалить из опций.

## Диагностика

- **`Mercury proxy is started with 0 of 1 meters`** — счётчик не ответил при старте:
  смотрите строку `Cannot connect to meter ... via ...` рядом. Сервис продолжит
  пробовать каждые `reconnect_interval` секунд; проверьте путь к порту, питание
  счётчика и провода A/B.
- **`ConfigError` при старте** — сообщение называет параметр (например,
  `api.token must be at least 8 characters`): сервис умышленно падает при
  некорректной конфигурации, а не посреди запроса.
- **`API has no token: anyone who can reach 0.0.0.0:5054 can read the meters`** —
  API без ключа. Либо задайте `api_token`, либо ограничьте доступ к порту 5054.
- **`Package from ... has wrong checksum`** — в прокси-порт пришёл пакет с неверной
  CRC; обычно это значит, что клиент говорит не на протоколе V1.
- **`No meter is addressed by the package from ...`** — адрес из пакета не совпадает
  ни с одним счётчиком из опции `meters` (адрес — полный серийный номер).
- **`Meter ... did not answer the package from ...`** — счётчик подключён, но на этот
  запрос не ответил: занятая шина, неверная скорость или сбой счётчика.
- **`The request from ... looks like HTTP, the proxy speaks the meter protocol`** —
  в прокси-порт постучались HTTP-запросом; сервис закрывает такое соединение.
  REST API живёт на порту 5054.
